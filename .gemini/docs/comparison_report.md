# Сравнение функционала: DICOM TPS Harmonizer vs DicomFix

Этот отчет содержит сравнение функционала нашего проекта **DICOM TPS Harmonizer** с решением **DicomFix-Community** и предлагает рекомендации по улучшению нашего проекта.

---

## 1. Сравнительная таблица функционала

| Функциональная возможность | DICOM TPS Harmonizer (Наш проект) | DicomFix (DicomFix-Community) | Анализ различий |
| :--- | :--- | :--- | :--- |
| **Разделение мультифреймов (Multi-frame Splitting)** | **Есть**. Преобразует Enhanced DICOM (многокадровые файлы) в классические single-frame срезы. | Не заявлено как ключевой функционал. | Преимущество нашего проекта, критически важное для старых систем планирования (TPS). |
| **Декомпрессия Pixel Data (Transcoding)** | **Нет**. Считывает массивы пикселей "как есть". Если файл сжат (например, JPEG Lossless/RLE), импорт в TPS может завершиться ошибкой. | **Есть**. Автоматически распаковывает сжатые пиксели (JPEG Lossless, RLE) в сырой `Implicit VR Little Endian`. | Нашему проекту не хватает возможности декомпрессии сжатых DICOM-файлов. |
| **Контроль идентификационных данных (Identity Compliance)** | **Базовый**. Автоматически подставляет `"UNKNOWN"`, если теги имени или ID пациента пусты. | **Продвинутый**. Валидирует `PatientName` и `PatientID` на ограничения длины Value Representation (VR). Предлагает интерактивное UI-окно для их ручного изменения. | Наш проект делает автозамену silently. DicomFix дает оператору контроль через UI. |
| **Заполнение обязательных Type 1 тегов** | **Базовое**. Заполняет несколько тегов по умолчанию (`AccessionNumber`, `ReferringPhysicianName` и т.д.). | **Продвинутый**. Восстанавливает отсутствующие обязательные параметры сканирования (MR Acquisition, Scanning Sequence), требуемые строгими TPS. | Нам нужно расширить список обязательных тегов, специфичных для модальностей (особенно MRI). |
| **Разделение серий (Geometric Segregation)** | **Частично**. Просто исключает сервисные файлы (топограммы, отчеты о дозах) по ключевым словам в `SeriesDescription`. | **Есть**. Анализирует геометрию (`ImageOrientationPatient`, `ImagePositionPatient`) и автоматически разделяет смешанные серии (например, scout-сканы от основного объема). | DicomFix разделяет смешанные серии геометрически, предотвращая сбои 3D-реконструкции в TPS. |
| **Очистка приватных тегов (Private Tags Purge)** | **Есть**. Опция `clean_tags` полностью удаляет все приватные (non-standard) теги. | **Есть**. Удаляет невалидные или поврежденные приватные теги. | Функционал эквивалентен. |
| **Восстановление битых файлов (Siemens EOF Fix)** | **Есть**. Автоматически дописывает маркер конца последовательности для усеченных файлов Siemens. | Не заявлено явно. | Преимущество нашего проекта. |
| **Организация выходных папок** | **Фиксированная**. Создает красивую иерархию по пациентам и сериям. | **Копирование**. Воссоздает исходную древовидную структуру папок источника. | В нашем проекте структура более упорядочена, но у DicomFix есть гибкость для пакетной обработки. |
| **Интерфейс пользователя (UI/UX)** | Простой GUI на `CustomTkinter` с выводом текстовых логов и прогресс-баром. | Продворный интерфейс рабочей станции: дерево файлов, таблица диагностики (Diagnostic Console) с тултипами ошибок и просмотрщик снимков. | GUI DicomFix значительно более информативен и ориентирован на диагностику до запуска конвертации. |

## 2. Предлагаемые улучшения для DICOM TPS Harmonizer

На основе проведенного анализа предлагается внедрить следующие улучшения (от простых к сложным):

### Приоритет 1: Декомпрессия сжатых DICOM-файлов (Transcoding)
* **Проблема:** Если исходные DICOM-файлы сжаты с потерей или без потери качества (например, `JPEG Lossless`, `JPEG 2000`, `RLE Lossless`), то при простом копировании или разделении кадров планирующая система (TPS) может не принять их, так как Aria/Monaco требуют несжатый `Implicit/Explicit VR Little Endian`.
* **Решение:** Интегрировать автоматическую декомпрессию пикселей при чтении с помощью `pydicom` совместно с библиотеками декодирования (например, `pylibjpeg`, `openjpeg` или `numpy` декодирование). Перед обработкой приводить любой Transfer Syntax к `Explicit VR Little Endian` или `Implicit VR Little Endian`.

### Приоритет 2: Геометрическое разделение смешанных серий (Geometric Segregation)
* **Проблема:** Иногда в одной папке или даже в рамках одной серии (по метаданным) лежат как сканы-локализаторы (scout/localizer), так и основные срезы 3D-объема. Если загрузить их в TPS вместе, возникнет ошибка реконструкции.
* **Решение:** Анализировать вектор ориентации (`ImageOrientationPatient`) и шаг координат. Снимки с существенно отличающейся ориентацией (например, ортогональные скауты) или выбивающиеся из общей регулярной сетки координат автоматически выделять в отдельную подсерию (с генерацией нового `SeriesInstanceUID`).

### Приоритет 3: Интерактивная валидация данных пациента (Identity Compliance)
* **Проблема:** Автоматическая замена пустых значений на `"UNKNOWN"` не всегда подходит для клинической практики, так как затрудняет идентификацию пациента в общей базе TPS.
* **Решение:** Если при сканировании файлов обнаружены пустые или невалидные теги `PatientName` / `PatientID` (превышающие лимиты длины VR или содержащие запрещенные символы), перед запуском обработки показывать оператору диалоговое окно для ручного ввода корректных данных с возможностью применить их ко всему пакету.

### Приоритет 4: Расширение исправления Type 1 тегов для МРТ
* **Проблема:** Для успешного импорта МРТ-серий в TPS Varian Aria часто требуются специфические теги последовательности сканирования (например, `ScanningSequence`, `SequenceVariant`, `ScanOptions`, `MRAcquisitionType`), которые могут отсутствовать в экспортированных из PACS файлах.
* **Решение:** Добавить автоматическое заполнение этих тегов дефолтными совместимыми значениями (например, `MRAcquisitionType` = `3D` или `2D` на основе анализа координат срезов) при включении опции "Заполнять обязательные теги".

### Приоритет 5: Интерактивная таблица диагностики в GUI (Diagnostic Console)
* **Проблема:** Сейчас пользователь видит проблемы только постфактум в текстовом логе.
* **Решение:** Добавить в GUI предварительный анализ (кнопку "Анализ" / "Scan"), который выведет таблицу файлов с указанием обнаруженных несовместимостей (например: *«Файл сжат (JPEG Lossless)»*, *«Отсутствует SliceLocation»*, *«Невалидный ID пациента»*) и предложенными действиями до фактической записи файлов.
